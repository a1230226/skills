# 会议材料整理输入示例

> **版本**: v1.0.0
> **用途**: 用于把会议纪要、聊天记录或零散材料整理成可发送、可复用的文档
> **边界**: 本文档不负责工作流路由；工作流应由目标 Skill 根据“目的”和“提供的信息”判断

## 适用场景

- 用户已有会议纪要、聊天记录、草稿或资料链接。
- 目标产物是可发给团队、可继续 review 的 proposal、decision、runbook 或项目说明。
- 重点是先搬运信息、区分事实/假设/冲突，再补结构。

## 建议提供的信息

- 必需: 材料路径或粘贴内容、目标读者、最终文档用途。
- 必需: 哪些结论已经确认、哪些只是讨论中意见。
- 可选: 需要保留的原话、敏感信息处理要求、目标文件名、截止时间。

## 可直接复制输入模板

```markdown
使用 `kz-doc-coauthoring`，把 `{会议纪要/聊天记录/零散要点}` 整理成一份 `{目标文档类型}`。

材料位置：{文件路径、链接或粘贴内容}
目标读者：{谁会读}
文档用途：{发给团队同步/作为决策依据/作为操作手册}
已确认结论：{已经定下来的内容}
未确认或冲突点：{存在争议或来源不一致的内容}
目标文件：{DOC_PATH，如 proposal.md}

请先提取事实、假设、冲突和待确认项，再给出目录骨架。
```

## 真实输入示例（可选）

```markdown
使用 `kz-doc-coauthoring`，把今天的项目讨论记录整理成一份团队同步文档。

材料位置：docs/meeting-notes/import-discussion.md
目标读者：项目组成员和财务运营。
文档用途：同步导入能力的范围、下周行动项和待确认风险。
已确认结论：第一版只做 Excel 导入，不接入第三方系统。
未确认或冲突点：财务希望保留原表格式，研发倾向统一模板。
目标文件：proposal.md

请先提取事实、假设、冲突和待确认项，再给出目录骨架。
```

## 路由判断（可选）

该输入应进入 `step-context-gathering`；若用户明确只要最终审校已有文档，则进入 `step-final-review`。
