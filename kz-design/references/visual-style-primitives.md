# 视觉风格 Primitives

> **版本**: v1.0.2
> **用途**: 当用户要求配色、布局、主题、视觉风格或多方向探索时，提供可组合的颜色与布局决策材料

## 使用规则

- style profile 决定审美方向；visual primitives 决定配色策略、布局语法和形态密度；theme package 把决策翻译成可复用 tokens。
- 不先套主题名。先判断内容、受众、媒介、品牌资产和信息密度，再选 1 个配色策略 + 1 个布局语法 + 1 个形态密度。
- 每个方向最多选择 1 个主配色策略和 1 个主布局语法；辅助手段只允许补一个，不平均混搭。
- 配色必须写成 token 角色，不只给 hex：`primary`、`accent`、`surface`、`text`、`border`、`success/warning/danger/info`。
- 布局必须服务信息关系，不只追求新奇构图；操作型界面优先效率，品牌/发布页才优先首屏张力。
- 形态密度必须服务使用场景；圆角、间距和信息密度要一起决定，不要只因为“高级”就放大圆角和留白。
- 外部主题库可以作为灵感或输入源，但不要把固定主题当成默认答案；必须先转换为本 Skill 的 Theme Package。

## 配色策略

| 策略 | 适合 | 核心做法 | 主风险 |
|---|---|---|---|
| 品牌提取型 | 具体品牌、产品、活动 | 从真实 Logo、产品图、官网或截图提取主色和辅助色 | 凭记忆配色、过度偏离品牌 |
| 中性底单强调 | B2B、工具、报告、后台 | 大面积中性 surface + 1 个清晰 accent | 太冷、缺少记忆点 |
| 编辑双色型 | 观点页、报告、叙事页 | 深浅主色 + 少量章节强调色 | 像杂志但流程弱 |
| 暖材质型 | 生活方式、文化、消费品牌 | 暖中性色 + 低饱和强调色 + 材质感 | 甜腻、米色化 |
| 高对比海报型 | 发布页、活动、实验视觉 | 深浅强对比 + 少量高能 accent | 炫技压过内容 |
| 功能语义型 | Dashboard、工具、状态系统 | 中性色 + 稳定功能色 + 状态色体系 | 状态色混乱、假复杂 |

### 品牌提取型

- token recipe: `primary` 来自品牌主色；`accent` 来自产品高光或 CTA；`surface` 从真实页面背景提取；`text` 和 `border` 保持高对比。
- 布局搭配: 海报锚点、对比画廊、编辑栏栅。
- 验证重点: Logo、产品图和 UI 截图是否与色彩一致；不要凭记忆造品牌色。
- 禁止事项: 不用“看起来像”的近似色冒充官方色；没有来源时标注待确认。

### 中性底单强调

- token recipe: `surface` 使用白、浅灰或低饱和暗色；`primary` 稳定；`accent` 只用于主动作、选中和关键数据。
- 布局搭配: 工作台分区、高密度矩阵、编辑栏栅。
- 验证重点: 扫描效率、状态区分、按钮层级和表格可读性。
- 禁止事项: 不把每个卡片、标题和图标都染成强调色。

### 编辑双色型

- token recipe: `primary` 作为标题和结构色；`accent` 作为章节焦点；`surface` 保留纸面或暗面质感。
- 布局搭配: 编辑栏栅、时间线叙事、对比画廊。
- 验证重点: 标题、引文、图像和正文之间是否形成阅读节奏。
- 禁止事项: 不用多色把每个章节都做成独立主题。

### 暖材质型

- token recipe: `surface` 使用暖白、纸色、木石或自然中性色；`accent` 低饱和；`text` 使用深墨或深棕灰。
- 布局搭配: 编辑栏栅、时间线叙事、海报锚点。
- 验证重点: 是否亲近但仍专业，CTA 是否清楚。
- 禁止事项: 不让页面变成全米色、全粉色或低对比。

### 高对比海报型

- token recipe: `surface` 一深一浅形成强反差；`accent` 只用于主记忆点；`text` 必须有可靠对比。
- 布局搭配: 海报锚点、对比画廊、时间线叙事。
- 验证重点: 3 秒内是否知道主题，强视觉是否遮挡信息。
- 禁止事项: 不把高对比等同于霓虹赛博，不默认深蓝紫。

### 功能语义型

- token recipe: `primary` 代表主动作；`success/warning/danger/info` 代表状态；`surface` 和 `border` 服务分区；`accent` 少用。
- 布局搭配: 工作台分区、高密度矩阵、时间线叙事。
- 验证重点: 同一种状态在表格、Tag、图表和按钮中是否语义一致。
- 禁止事项: 不用随机颜色区分数据；不要让状态色和品牌色互相冲突。

## 布局语法

| 语法 | 适合 | 核心做法 | 主风险 |
|---|---|---|---|
| 海报锚点 | Landing、品牌页、发布页 | 首屏一个大视觉 + 窄文本列 + 明确 CTA | 视觉弱或文字压图 |
| 编辑栏栅 | 报告、观点、长内容 | 大标题、窄栏正文、跨栏图、章节节奏 | 只好看不导向 |
| 工作台分区 | 工具、后台、AI 工作流 | 主工作区 + 导航 + 次级上下文/检查器 | 卡片马赛克 |
| 高密度矩阵 | 数据页、监控、控制台 | 多面板、表格、筛选、状态条，但层级严格 | 复杂到不可扫 |
| 时间线叙事 | 动画、流程、发布故事 | 步骤、里程碑、前后对比、渐进揭示 | 变成普通步骤列表 |
| 对比画廊 | 多方案、作品、商品、案例 | 网格、局部特写、并排比较、筛选 | 画面碎、缺主焦点 |

### 海报锚点

- 结构: full-bleed 或大画面区域 + 品牌/产品名 + 一句 promise + 一个 CTA。
- 适合: 品牌、产品发布、场馆、作品集、活动。
- 验证重点: 隐藏导航后仍能识别品牌/产品；图片删除后页面不应仍然成立。
- 禁止事项: 不在 hero 里堆统计条、标签云、logo 云、浮动 dashboard。

### 编辑栏栅

- 结构: 章节编号、大标题、窄栏正文、跨栏图像、引文或数据摘录。
- 适合: 观点、报告、品牌故事、研究解读。
- 验证重点: 只扫标题和图注能否理解主线。
- 禁止事项: 不把长内容拆成一堆同质卡片。

### 工作台分区

- 结构: 左导航/顶部工具栏 + 主工作区 + 右侧检查器/上下文面板。
- 适合: Dashboard、编辑器、管理后台、AI Agent 工作台。
- 验证重点: 用户下一步动作是否明确，常用信息是否不需要滚动寻找。
- 禁止事项: 不做营销 hero，不把每个区域都做成厚重卡片。

### 高密度矩阵

- 结构: 状态概览、筛选、表格、图表、日志或队列按优先级排列。
- 适合: 监控、情报分析、多状态系统、运营看板。
- 验证重点: 最高优先级状态是否先被看见，颜色是否只服务状态。
- 禁止事项: 不用假数据和过多状态点制造复杂感。

### 时间线叙事

- 结构: 起点、转折、焦点、结果；可用 sticky、stepper、镜头或 before/after。
- 适合: 动画、产品故事、流程解释、发布叙事。
- 验证重点: 每一步是否推动理解，而不是重复同一句卖点。
- 禁止事项: 不把每段都做成独立淡入淡出。

### 对比画廊

- 结构: 主焦点 + 多项并排 + 局部特写或差异标签。
- 适合: 多方案探索、案例展示、商品比较、作品集。
- 验证重点: 用户能否快速比较差异，而不是只看到一堆缩略图。
- 禁止事项: 不让网格变成无主次的图片墙。

## 组合协议

- 方向探索输出格式: `profile + 配色策略 + 布局语法 + 形态密度 + 主记忆点 + 风险 + 最小 demo 计划`。
- UI 规范输出格式: 在 `ui-spec.md` 中写 `Theme Package`，把配色策略翻译成 token，把布局语法翻译成区块结构和响应式规则，把形态密度翻译成 radius、spacing、density tokens。
- 实现交接输出格式: 在 `implementation-handoff.md` 中把 tokens 映射到目标系统 theme，把布局语法映射到目标组件或 layout primitives。
- 若用户要求“更高级”，至少给 2 种不同解释：克制可信的中性底单强调、叙事感的编辑双色型、发布感的高对比海报型。
- 若用户要求“换一套配色”，先判断是要换气质、换品牌、换可读性，还是换状态语义；不要只替换主色。

## 形态密度

| 密度 | 适合 | radius / spacing 倾向 | 主风险 |
|---|---|---|---|
| 锐利紧凑 | 数据密集后台、表格、编辑器、监控 | 小圆角、紧凑间距、强对齐 | 太硬、压迫感 |
| 柔和均衡 | 企业 SaaS、管理面板、通用 Web App | 中小圆角、标准间距、稳定分组 | 像默认组件库 |
| 圆润宽松 | 消费产品、内容浏览、社区、轻量工具 | 中大圆角、宽松内边距、友好触控 | 信息密度不足 |
| 胶囊通透 | 移动 H5、品牌展示、轻 CTA 页面 | 胶囊按钮、大留白、轻边界 | 过度营销化 |

### 形态密度规则

- 信息密度决定间距：表格、筛选、日志、控制台优先紧凑；内容浏览、品牌叙事、移动触控优先宽松。
- 外层圆角应大于或等于内层圆角；容器、图片、按钮的圆角不要互相打架。
- 同一组件组保持一致形态：卡片、按钮、输入框、标签和弹层应共享同一密度语气。
- 圆角与尺寸成比例：小控件不要用过大圆角，大画布容器不要过度方硬，除非它服务于专业、工程或数据气质。
- 形态密度不是审美主题；它只负责把 `profile` 的语气落到 radius、spacing、density tokens。

## 外部主题引入协议

- 可引入：主题名称、视觉意图、适用场景、颜色角色、字体配对和对比说明。
- 不默认引入：整套固定预设库、展示 PDF、未使用的主题文件、与当前任务无关的主题列表。
- 引入步骤：
  1. 读取用户指定的主题文件或主题描述。
  2. 把颜色从“命名色块”转换为 token：`primary`、`accent`、`background`、`surface`、`text`、`border`、状态色。
  3. 把字体配对转换为 `display`、`body`、`mono/code`。
  4. 写出 `best used for`、`contrast notes` 和 `do not use`。
  5. 再根据当前任务选择布局语法；不要只因主题好看就覆盖信息架构。
- 若外部主题与反 AI slop 或品牌事实冲突，优先按品牌事实、可读性和媒介适配修正主题。
- 若要把外部主题随 Skill 一起发布，必须同时处理许可证、署名和维护边界；默认不把外部主题资产打包进本 Skill。
