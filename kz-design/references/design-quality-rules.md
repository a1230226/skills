# 设计质量规则

> **版本**: v1.0.2
> **用途**: 为视觉产出提供硬约束，防止事实错误、素材缺失和通用 AI 审美

## 事实规则

- 涉及 2024 年之后的产品、公司、模型、版本、发布状态、价格和规格时，必须联网查证。
- 查不到权威来源时，用“未确认”或“待用户提供”标注，不把猜测写进设计文案。
- 设计物料涉及第三方品牌时，优先官方来源；无法确定授权时，不暗示官方合作。

## 核心资产协议

按识别度处理资产：

| 资产 | 适用场景 | 规则 |
|---|---|---|
| Logo | 所有品牌任务 | 有就必须用；没有就问、搜或标缺口 |
| 产品图 | 实体产品 | 优先官方产品页、press kit、发布视频截帧 |
| UI 截图 | 数字产品 | 优先官网、App Store、产品演示或用户真实截图 |
| 色值 | 所有品牌任务 | 从规范或真实页面提取，不凭记忆 |
| 字体 | 有品牌规范时 | 遵循规范；没有时选择能支撑气质的 display/body 组合 |

素材质量低于可用线时不要硬塞。设计里的低质量素材会比空白更伤害信任。

## 反 AI slop 清单

默认避免以下视觉套路：

- 紫蓝渐变、赛博霓虹、深蓝科技底作为泛用“高级感”。
- 装饰性 emoji、每条标题都配 icon、无意义状态点和无意义数据。
- 圆角卡片叠卡片、左色条 accent、大片玻璃拟态但没有品牌依据。
- 用 SVG/CSS 手画人物、产品、复杂场景来替代真实图像。
- Inter、Roboto、system font 全场做 display，且没有任何排版个性。
- 只有 stock photo 氛围图，却和内容没有内在关系。

允许破例的理由只有三类：品牌规范明确如此、用户明确指定、产物本身是在展示反例。

## 媒介适配规则

- 原型：用户必须能感受流程、状态和关键交互，不只是静态摆拍。
- 幻灯片：每页只有一个主信息，固定画布，字号适合演讲环境。
- 信息图：数据、注释和阅读顺序优先于装饰。
- 动画：每个镜头服务叙事，时间轴有节奏，不做一组 PowerPoint 切换。
- 移动 App mockup：先决定 overview 平铺还是 flow demo；overview 用于设计走查，flow demo 用于演示路径。

## 概念方向规则

- 动手前写一句 `aesthetic thesis`：这个界面服务谁、是什么语气、哪个细节最该被记住、复杂度边界在哪里。
- 每个产物只保留 1 个主记忆点：可以是字体、空间构图、关键动效、材质或真实素材表达之一；其它元素要服务它。
- 每个 section、屏幕或镜头只承担 1 个主要任务；如果同一段同时在解释、证明、转化和炫技，先拆分或删减。
- 实现复杂度必须匹配审美目标：克制型靠排版、间距和对齐取胜；表达型才增加复杂动效、纹理和层次，而且必须能回到任务场景。
- 动效优先做 1 个编排清楚的高影响时刻，不把很多零散 hover 和微交互堆满页面。

## 首屏识别测试

用于 landing、品牌页、产品介绍、作品集、场馆页和发布页；不强加给操作型工具界面。

- 品牌、产品或对象名在首屏必须清楚，不只藏在导航或角标里。
- 首屏必须有一个真实视觉锚点，能说明产品、地点、对象、场景、状态或体验；纯渐变、纹理和装饰背景不算。
- Hero 不默认使用卡片、统计条、logo 云、标签堆、浮动 dashboard 或多块小组件来撑满画面。
- 首屏移除主视觉后若仍然成立，说明主视觉太弱；隐藏导航后若品牌消失，说明层级太弱。
- 如果首屏有固定 header，首屏内容和 header 必须共同适配常见桌面与移动视口，不让 CTA、标题或主体图被挤出第一屏。

## 视觉硬约束

- 不让 UI 卡片套进页面卡片；重复列表项可以是卡片，页面区块不要都做成漂浮卡。
- 文字不得遮挡图像主体、按钮、设备框、字幕或下一段内容。
- 固定格式元素要有稳定尺寸：棋盘、设备框、图表、工具栏、slide、动画 stage 都不能被 hover 或动态文本撑变形。
- 字号不随 viewport 宽度无限缩放；最长词必须能放进容器。
- 配色不能读成单一色相堆叠；若整页被紫、深蓝、米色、棕橙等单一主题统治，需要主动修正。
